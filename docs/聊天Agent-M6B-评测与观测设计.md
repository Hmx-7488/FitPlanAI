# 聊天 Agent M6B：评测与观测设计

> 日期：2026-08-13
> 状态：方案已冻结，进入开发
> 前置阶段：[[聊天Agent-M6A-Tool-Calling实现记录]]

## 1. 决策摘要

M6B 先于写工具开发。当前 M6A 已解决“Agent 能否受控地选择并调用只读工具”，M6B 继续解决“如何证明选择正确、检索有效、回答有依据、故障可降级且成本可接受”。完成 M6B 后，再进入 M6C 的“草案 → Diff → 用户确认 → CAS 写入”闭环。

本阶段冻结以下决策：

1. 建立首版 60 条人工标注评测集，后续只新增版本，不覆盖历史基线。
2. keyword、vector、hybrid 三模式都保留为可评测通道；生产默认仍为 hybrid，不重新讨论是否采用混合检索。
3. CI 只运行确定性评测和假模型路由；真实 qwen 评测显式触发并保存带日期的报告。
4. 生产观测不保存原始问题、Prompt、Tool 参数正文、Tool 返回正文、记忆正文或健康敏感文本。
5. M6B 只读、不新增业务写权限；M6C 第一条写闭环固定为聊天热量调整草案。

## 2. 目标与非目标

### 目标

- 量化 Tool 选择、混合检索、上下文可见性、回答依据、安全和工程性能。
- 将一次聊天拆成可追踪的 Agent Run、Tool Run、Retrieval Run 和 Context Build。
- 区分“查到”“进入模型上下文”“被回答引用”三个阶段，避免观测口径混淆。
- 输出可复现的版本化报告，为 RRF、候选窗口、Prompt 和模型升级提供数据依据。
- 形成可以诚实写入简历的实测指标，不使用构造样例冒充生产数据。

### 非目标

- 不在本阶段开放修改计划、档案、餐食或打卡的工具。
- 不用 LLM-as-Judge 作为唯一正确性裁判。
- 不建设复杂运营大屏；第一版提供 CLI、JSON 报告和受保护的聚合诊断接口。
- 不为了展示技术栈引入外部 MCP、第三方 Memory SaaS 或新的向量数据库。

## 3. 首版 60 条评测集

用例按主测试意图互斥分类，避免同一问题重复计数：

| 分类 | 数量 | 主要覆盖 |
| --- | ---: | --- |
| 无工具问题 | 10 | 问候、闲聊、常识解释、不应调用工具 |
| 单工具问题 | 12 | 档案、计划、打卡、餐食、食物、动作、知识、记忆 |
| 多工具问题 | 10 | 计划与打卡对比、动作与依据、餐食与目标对比 |
| 记忆与三模式检索 | 10 | 跨会话偏好、冲突、替代、过期、keyword/vector/hybrid |
| 长上下文与摘要 | 8 | 早期目标、关键数字、否定、未完成事项、最新纠正 |
| 安全与提示注入 | 6 | 越权、伪造 user_id、要求写数据、高风险健康问题 |
| 故障与降级 | 4 | Planner、Tool、Embedding、Chroma 故障及部分成功 |
| 合计 | 60 | 首版冻结规模 |

每条用例至少包含：

- `case_id`、`dataset_version`、分类和用户问题；
- 允许/必须/禁止的工具集合；
- 期望来源、记忆 ID 或关键事实；
- 是否要求引用、拒答、风险提示或关键词降级；
- 不变量断言，例如不得跨用户、不得使用已删除记忆；
- 可选的人工评分说明，不保存真实用户隐私数据。

## 4. 指标定义

### 4.1 Tool 选择

- Exact Match：最终工具集合是否与标注完全一致。
- Precision / Recall：多工具问题中多调和漏调情况。
- Unnecessary Tool Rate：无需工具的问题发生调用的比例。
- Disallowed Tool Calls：不存在、写入型或越权工具调用次数，必须为 0。
- Partial Failure Completion：部分工具失败时，能否保留成功结果并安全完成回答。

### 4.2 长期记忆与混合检索

- Recall@K：标注相关记忆是否进入 Top-K。
- MRR：第一条相关记忆的倒数排名均值。
- Hard Constraint Miss Rate：伤病、过敏等必须召回事实的漏召回率。
- Stale Filter Count：被 fingerprint/revision/生命周期终检过滤的陈旧向量数。
- Deleted/Rejected/Expired Usage：被删除、拒绝或过期记忆进入上下文的次数，必须为 0。
- 三模式分别记录延迟、降级率、召回质量与 embedding 调用成本。

### 4.3 上下文与回答

- Context Availability：回答所需事实是否真实进入模型上下文。
- Summary Fidelity：摘要是否保留数字、否定、限制、待办和最新纠正。
- Citation Coverage：回答中的可验证结论是否具有实际保留的来源。
- Grounded Answer Rate：回答是否只使用本轮提供的业务数据与证据。
- Safety Constraint Adherence：健康硬约束是否遵守。
- Cross-session Task Completion：跨会话追问是否能利用已确认长期记忆完成任务。

### 4.4 工程指标

- 总耗时、首 Token 延迟、Tool/检索/Context Build 分段耗时；
- 输入、输出和总 Token；
- Tool 数、实际进入上下文的 Artifact 数、Microcompact 次数和节省 Token；
- Planner、Tool、Retrieval、Model 的错误与降级原因；
- 按模型和单价版本计算的估算成本；
- p50/p95 只在样本量足够时展示，不能用少量样本伪装生产分位数。

## 5. 内容无关观测设计

建议新增两层记录：

### Agent Run

- `run_id`、会话/消息引用、环境、模型和 Prompt 版本；
- 开始/结束时间、状态、总耗时和首 Token 延迟；
- Tool 选择数、成功数、上下文纳入数；
- Token、成本、降级阶段和稳定错误码；
- 评测流量使用 `case_id`，生产问题只保留部署密钥生成的 HMAC 指纹用于重复率分析。

### Tool Run

- `run_id`、服务端生成的 `call_id`、工具名和状态；
- 耗时、来源数量、是否进入上下文、稳定错误码；
- 参数只保存 schema 版本和 HMAC 指纹，不保存参数正文；
- 不保存 SQL、Tool 结果正文、原始记忆或图片数据。

现有 `UserMemoryRetrievalRun/Hit` 继续负责记忆检索通道、排名和实际上下文使用状态，不复制正文。消息 `context_json` 保留面向单次回答的安全诊断；聚合查询使用独立观测记录，避免长期扫描消息 JSON。

## 6. 评测执行分层

```text
确定性 CI
  ├─ Fixture/schema 校验
  ├─ Context availability
  ├─ keyword/vector/hybrid 固定召回
  ├─ 假 Planner 工具选择与越权断言
  └─ 故障降级与状态机回归

显式真实模型评测
  ├─ qwen Tool 路由
  ├─ 最终回答与引用人工复核
  ├─ Token/延迟/成本
  └─ 带日期、模型和 Prompt 版本的不可覆盖报告

生产内容无关观测
  ├─ Agent Run / Tool Run
  ├─ Retrieval Run
  └─ 聚合成功率、延迟、降级和成本
```

## 7. 开发切片

### M6B-1：评测契约与报告器

- 建立 60 条版本化 fixture 的 schema、唯一性和分类数量校验。
- 复用生产 Tool schema、检索器和 Context Builder，禁止复制一套“只为评测通过”的逻辑。
- 输出机器可读 JSON 和面向文档的 Markdown 摘要。

### M6B-2：三模式检索与长上下文评测

- 固定比较 Recall@K、MRR、硬约束漏召回、延迟和降级。
- 补齐摘要事实保持、冲突处理和跨会话记忆用例。
- 形成首版基线，之后才允许调整 RRF 与候选窗口。

### M6B-3：内容无关生产观测

- 接入 Agent Run / Tool Run，记录分段耗时、Token、成本和降级。
- 增加受保护的聚合诊断接口或导出命令。
- 验证日志、数据库和 API 均不泄露原始敏感内容。

### M6B-4：真实 qwen 基线与文档

- 显式运行真实模型固定集并人工复核。
- 保存模型、Prompt、数据集和价格版本。
- 将实测结果同步到 [[AI应用与AI-Agent项目亮点]]，未测指标继续标记为待量化。

## 8. 验收标准

1. 60 条 fixture 数量、ID、分类和 schema 由自动化测试约束。
2. Tool、Retrieval、Context、Answer、Safety、Latency/Token/Cost 均有明确定义和报告字段。
3. keyword/vector/hybrid 使用同一标注集，可重复比较 Recall@K 与 MRR。
4. 越权工具调用、跨用户读取、未确认写入、已删除记忆使用次数均为 0。
5. CI 不依赖真实模型或网络；真实模型评测必须显式触发。
6. 观测数据不包含原始问题、Prompt、Tool 正文、记忆正文、图片或视频内容。
7. 报告包含数据集、模型、Prompt、价格和代码版本，历史基线不可覆盖。
8. 全量后端测试、前端构建和安全审查通过。

建议目标如“记忆召回达到 90%”或“上下文 Token 降低 40%”只作为待验证假设，不在首轮测量前写成既成事实。

## 9. 后续冻结路线

1. M6B：评测与内容无关观测。
2. M6C：`AgentChangeDraft` 通用草案状态机；第一条纵向闭环为热量调整。
3. M6C 扩展：食材替换、餐次调整、训练动作替换。
4. M6D：最小、版本化页面快照；权威数据仍由服务端 Tool 查询。
5. 外部 MCP：仅在接入日历、可穿戴设备或第三方数据源时评估。
