# 上下文与记忆 M0 基线报告

## 1. 目的

在引入 token 预算、会话摘要和长期记忆前，先量化当时“最近 10 条消息”策略能否把回答所需事实提供给模型。本报告保存的是 **M1/M2 改造前基线**，不是当前运行策略；它作为后续 M1-M6 的固定对照。

这不是 LLM 回答质量评测。它只判断关键事实是否实际出现在模型可见的动态上下文中。如果事实不可见，模型即使偶然答对也不代表上下文系统可靠。

## 2. 改造前策略核对

代码行为：

1. 当前用户消息先写入 `chat_messages`。
2. 查询当前会话最新 10 条消息。
3. 构建历史时跳过当前用户消息。
4. 最后显式追加当前用户消息。

因此实际最多是 **9 条历史消息 + 1 条当前消息**，而不是 10 条历史消息。

当前能力：

| 能力 | 状态 |
| --- | --- |
| 最近消息窗口 | 10 行查询，最多 9 条既有历史进入模型 |
| 用户正式档案 | 支持 |
| 最新计划 | 支持 |
| 页面上下文 | 支持 |
| 单会话摘要 | 不支持 |
| 跨会话召回 | 不支持 |
| 长期用户记忆 | 不支持 |
| token 动态预算 | 不支持 |

## 3. 评测集

固定用例文件：[context_memory_cases.json](../backend/tests/fixtures/context_memory_cases.json)

| 用例 | 类型 | 当前是否可见 |
| --- | --- | --- |
| 近期早餐偏好 | 同会话近期信息 | 是 |
| 长对话早期阶段目标 | 同会话早期信息 | 否 |
| 正式档案中的严重过敏 | 权威档案 | 是 |
| 只在早期聊天提到的膝伤 | 敏感但未写入档案 | 否 |
| 旧会话中的稳定忌口 | 跨会话 | 否 |
| 近期训练频率纠正 | 冲突与近期覆盖 | 是 |

## 4. 基线结果

执行日期：2026-08-11

执行命令：

```powershell
cd backend
python -m app.evals.context_memory
```

结果：

| 指标 | 基线 |
| --- | ---: |
| 总用例 | 6 |
| 关键事实可见 | 3 |
| Context availability | 50.0% |
| 安全相关用例 | 2 |
| 安全事实可见 | 1 |
| Safety context availability | 50.0% |
| 固定预期匹配 | 6 / 6 |

结论：当前策略能处理近期信息、正式档案信息和近期纠正，但无法可靠处理长对话早期目标、只存在于聊天中的敏感信息和跨会话偏好。

## 5. Token 说明

评测器同时输出 `estimated_dynamic_context_tokens`，使用与模型无关的保守估算：中文字符按 1 token、其他非空白字符约 4 字符/token。

该数值只用于同一评测集上的前后相对比较，不能作为账单或简历指标。生产环境最终以模型服务返回的 usage 数据为准。

当前 M0 用例的动态上下文估算约为 150-158 token；这不包含完整系统提示、RAG 文档和模型协议开销。

## 6. 自动化验证

测试文件：[test_context_memory_eval.py](../backend/tests/test_context_memory_eval.py)

覆盖：

- 评测 fixture 版本与用例 ID 唯一性。
- 六个用例的当前可见性结果。
- 当前最多 9 条既有历史消息的边界。
- 正式档案信息不受历史截断影响。
- 跨会话消息当前不可见。
- token 估算的确定性。
- 真实 `_load_agent_context` 查询最近 10 行且恢复升序。

本次执行结果：7 / 7 通过。

## 7. M1 对比要求

M1 引入 Context Builder 后至少重新测量：

- 当前 6 个用例的事实可见率不能回退。
- 每类上下文的估算 token 和裁剪原因可以观测。
- 权威健康档案不会因预算不足被裁剪。
- 超预算时优先裁剪低相关 RAG 和旧工具结果。
- 同一输入的上下文组装顺序保持确定性。

M2 引入会话摘要后，目标是让“早期阶段目标”和“早期膝伤候选”能够进入摘要或确认流程；M4 引入长期记忆后，再解决跨会话忌口召回。
