# 上下文与记忆 M1-M2 实现记录

## 1. 本轮范围

本轮完成 [[ADR-001-分层上下文与长期记忆]] 中的第一条纵向切片：

- M1：Token 预算、统一 Context Builder 和上下文诊断。
- M2：版本化会话摘要、覆盖游标、近期消息尾部和失败降级。

M1/M2 当轮不包含跨会话长期记忆、记忆确认 UI 和工具结果 Microcompact；这些能力后来已分别在 M3 和 M4 完成，详见关联文档。

## 2. M1：Token 预算与 Context Builder

新增 [context_builder.py](../backend/app/services/context_builder.py)，聊天服务不再固定把最近若干消息直接拼给模型。

### 2.1 可配置预算

```text
input_budget
= context_window
- max_output_tokens
- safety_buffer_tokens
```

默认配置：

| 配置 | 默认值 |
| --- | ---: |
| `CHAT_CONTEXT_WINDOW_TOKENS` | 32768 |
| `CHAT_CONTEXT_MAX_OUTPUT_TOKENS` | 1200 |
| `CHAT_CONTEXT_SAFETY_BUFFER_TOKENS` | 2048 |
| `CHAT_CONTEXT_MAX_HISTORY_MESSAGES` | 500 |

默认窗口是保守工程配置，不声称等于所有模型的真实上限；部署时必须按实际模型能力覆盖。配置会校验输出预留与安全缓冲不能填满窗口。

### 2.2 上下文优先级

Context Builder 按以下顺序保护信息：

1. 系统职责、健康安全规则和当前用户消息。
2. 权威用户档案。
3. 当前有效计划。
4. 页面业务上下文。
5. 最新有效会话摘要。

诊断与压缩策略使用稳定的模型无关 token 估算；硬预算门禁另用 UTF-8 字节数作为 tokenizer 无关的保守上界。基础系统规则、本轮消息和末尾数据边界均不可裁剪，如果三者无法放入配置预算，Builder 会在调用模型前明确拒绝，而不是发送可能溢出的请求。
6. 近期完整对话轮次。
7. 实际能够装入预算的 RAG 文档。

历史消息按完整 user/assistant turn 选择，预算不足时不会只保留助手答案而丢掉对应用户问题。当前用户消息会按消息 ID 去重，避免“数据库历史中一次 + 显式追加一次”。

### 2.3 引用一致性

如果某条 RAG 文档因为预算不足没有发送给模型，对应 citation 也不会随响应返回，避免展示“模型本轮没有看到的来源”。

### 2.4 诊断信息

每条助手消息的 `context_json` 和 SSE `meta` 事件现在包含：

- 上下文窗口、输出预留、安全缓冲和输入预算。
- 估算输入 token。
- 各组件估算 token。
- 历史加载、保留和丢弃数量及保留消息 ID。
- RAG 检索数量与实际注入数量。
- 使用的摘要 ID 和覆盖游标。
- 被截断的组件和是否保持在预算内。

诊断只记录 ID、数量和 token，不额外复制完整敏感文本。

## 3. M2：会话摘要与覆盖游标

新增数据模型 `ChatConversationSummary`，表名为 `chat_conversation_summaries`。新表由现有 `create_all` 启动流程增量创建，不修改或删除旧聊天表。

主要字段：

- `conversation_id`
- `summary_json` / `summary_text`
- `covered_through_message_id`
- `source_message_count`
- `estimated_tokens`
- `model`
- `status`
- `error_type`
- 创建与更新时间

### 3.1 增量摘要

摘要器只读取最新完成摘要游标之后的消息，并在开始时固定本次目标消息 ID。成功后才生成新的 completed 版本；失败记录为 failed，不推进有效游标。

结构化摘要保存：

- 当前目标。
- 用户确认事实。
- 约束。
- 已做决定。
- 待确认问题。
- 待办。
- 用户纠正。

Prompt 明确把聊天内容视为待总结数据，禁止执行消息内指令；模型输出必须经过 JSON 解析和 Pydantic 校验。

### 3.2 近期尾部

摘要前根据 `CHAT_SUMMARY_KEEP_RECENT_TOKENS` 保留近期原始消息，且不会切开普通 user/assistant 对。被保留的尾部会继续参与下一轮 Context Builder，维持语气、指代和最近纠正。

### 3.3 非阻塞触发

聊天流结束后通过 StreamingResponse background task 检查是否需要摘要，当前回答不等待摘要模型。触发条件支持：

- 游标之后的消息估算 token 达到阈值。
- 游标之后的消息数量达到阈值。

同一进程内，同一会话使用异步锁避免重复任务；落盘前再次比较最新完成游标，旧任务不能覆盖覆盖范围更大的新摘要。

### 3.4 失败降级

- 无有效摘要：Context Builder 继续使用近期原始消息。
- 摘要模型或 JSON 校验失败：记录错误类型，不保存模型错误原文，不推进游标。
- 摘要任务失败不影响已经完成的聊天响应。
- 只读取 `completed` 摘要，pending/failed/superseded 不进入模型上下文。

## 5. 自动化验证

专项命令：

```powershell
cd backend
python -m unittest tests.test_chat tests.test_context_memory_eval tests.test_context_builder -v
```

本轮专项结果：25 / 25 通过。

完整后端回归：201 / 201 通过；`python -m compileall app tests` 通过。

覆盖内容：

- 权威档案在紧张预算下仍优先进入上下文。
- 输入估算不超过预算。
- 历史 turn 不被拆分。
- 被裁剪 RAG 的 citation 不返回。
- 摘要文本和游标进入上下文诊断。
- 当前消息不会重复。
- 配置拒绝无效预算。
- 摘要 token/消息数触发。
- 摘要边界不切开 user/assistant 对。
- 成功摘要持久化 completed 版本和覆盖游标。
- 非 JSON 模型输出记录 failed 且不产生有效摘要。
- 原有聊天流、失败和取消行为保持通过。
- SSE 流完成后会执行摘要后台检查。

## 6. 尚未量化与剩余风险

以下内容不能提前包装成完成指标：

- 尚未使用真实长对话和真实模型统计摘要事实保持率。
- 当前 token 数为模型无关的保守估算，生产成本应以供应商 usage 为准。
- 当前摘要互斥锁是进程内锁；多实例部署需要数据库锁、任务队列或唯一幂等约束。
- 后台任务依赖 Web 进程生命周期；生产部署需要持久任务队列保证进程重启后的任务可靠性。
- M1/M2 当轮未覆盖长期记忆、敏感信息确认、用户查看和删除；M4 已补齐第一版纵向切片。
- M1/M2 当轮未覆盖工具/RAG Microcompact；M3 已完成通用 Artifact 接口和聊天 RAG 接入。
