# 减脂 Agent 项目需求文档

## 1. 项目概述

减脂 Agent 是面向有减脂、塑形、健康饮食需求用户的智能健身与营养规划助手。产品结合用户身体数据、训练目标、饮食偏好、现有食材照片和执行反馈，为用户生成个性化训练计划、营养摄入目标、饮食建议与轻食烹饪方案。

项目初期重点服务健身教练、营养师和其学员，帮助教练提升计划制定效率，也帮助用户获得更清晰、可执行、可追踪的减脂方案。

## 2. 产品目标

1. 根据用户基础身体数据生成个性化减脂营养目标。
2. 根据用户训练水平、可训练时间、器械条件生成训练计划。
3. 根据用户现有食材照片识别食材，并生成轻食餐食方案。
4. 给出每日或每周饮食建议，帮助用户理解蛋白质、碳水、脂肪等营养摄入目标。
5. 支持用户持续反馈体重、围度、体脂变化和饮食执行情况，并动态调整方案。

## 3. 目标用户

### 3.1 C 端用户

- 想减脂但不知道怎么吃、怎么练的人。
- 有一定健身基础，希望获得结构化计划的人。
- 工作忙、希望用家里现有食材快速做轻食的人。
- 对热量和营养素没有系统认知，需要简单指导的人。

### 3.2 B 端用户

- 健身教练。
- 营养师。
- 私教工作室。
- 轻食餐饮或健康管理机构。

## 4. 核心使用场景

### 4.1 身体数据建档

用户填写或上传身体数据：

- 性别。
- 年龄。
- 身高。
- 体重。
- 体脂率。
- 肌肉量。
- 基础代谢率，如用户设备可提供。
- 训练经验。
- 训练频率。
- 目标体重或目标体脂率。
- 目标周期。
- 疾病史、伤病史、过敏源和忌口。

系统根据数据估算用户当前状态，并生成初始减脂目标。

### 4.2 营养摄入规划

系统根据用户身高、体重、肌肉量、体脂率、目标周期、训练频率等信息，输出每日建议摄入：

- 总热量，单位 kcal。
- 蛋白质，单位 g。
- 碳水化合物，单位 g。
- 脂肪，单位 g。
- 膳食纤维，单位 g。
- 饮水量，单位 ml。
- 可选：钠、钾、钙、铁等微量营养素建议。

示例输出：

```text
每日目标：
热量：1600 kcal
蛋白质：100 g
碳水：130 g
脂肪：45 g
膳食纤维：25 g
饮水：2200 ml
```

系统同时给出饮食建议：

- 每餐蛋白质来源建议。
- 主食选择建议。
- 蔬菜和膳食纤维建议。
- 训练日和休息日碳水调整建议。
- 外食、加餐、夜宵处理建议。

### 4.3 训练计划生成

用户输入训练条件：

- 每周可训练天数。
- 单次训练时长。
- 训练地点：家庭、健身房、户外。
- 可用器械：哑铃、杠铃、弹力带、跑步机、椭圆机等。
- 训练水平：新手、初级、中级、高级。
- 伤病限制。
- 偏好：力量训练、有氧、HIIT、瑜伽、普拉提等。

系统输出训练计划：

- 周训练安排。
- 每次训练目标。
- 动作名称。
- 组数、次数、间歇。
- 训练强度说明。
- 有氧时长和心率区间建议。
- 热身和拉伸建议。

示例：

```text
周一：下肢力量 + 中低强度有氧
深蹲 4 组 x 10 次
罗马尼亚硬拉 3 组 x 12 次
臀桥 4 组 x 12 次
椭圆机 25 分钟，心率控制在最大心率 60%-70%
```

### 4.4 轻食计划生成

用户拍摄家中现有食材照片，系统完成：

1. 识别食材种类。
2. 估算食材大致重量或提示用户补充重量。
3. 判断食材营养结构。
4. 结合用户当日剩余营养目标生成餐食方案。
5. 给出具体烹饪步骤。

输出内容包括：

- 可制作菜品名称。
- 所需食材及用量。
- 烹饪方式。
- 预计热量。
- 预计蛋白质、碳水、脂肪。
- 是否适合当前减脂阶段。
- 可替换食材建议。

示例：

```text
识别食材：鸡胸肉、鸡蛋、西兰花、番茄、玉米

推荐轻食：香煎鸡胸肉西兰花能量碗
鸡胸肉 150 g
西兰花 200 g
玉米 80 g
番茄 100 g
鸡蛋 1 个

预计营养：
热量：520 kcal
蛋白质：48 g
碳水：42 g
脂肪：14 g
```

### 4.5 执行反馈与计划调整

用户每日或每周反馈：

- 当前体重。
- 腰围、臀围、大腿围等围度。
- 体脂率变化。
- 饮食执行率。
- 训练完成率。
- 饥饿感。
- 疲劳感。
- 睡眠时长和质量。
- 经期状态，适用于女性用户。

系统根据反馈调整：

- 热量缺口。
- 碳水分配。
- 训练强度。
- 有氧频率。
- 平台期应对策略。

## 6. Agent 能力设计

### 6.1 输入能力

- 文本输入：身体数据、目标、偏好、反馈。
- 图片输入：食材照片、体测报告截图、餐食照片。
- 结构化表单：用户档案、训练条件、忌口信息。

### 6.2 推理能力

- 身体状态评估。
- 热量缺口估算。
- 三大营养素分配。
- 食材营养匹配。
- 训练计划编排。
- 风险识别和安全提醒。

### 6.3 输出能力

- 结构化计划。
- 每日餐食建议。
- 轻食烹饪步骤。
- 训练动作清单。
- 周复盘报告。
- 可分享给教练或用户的总结卡片。

## 8. 计算与规则初稿

### 8.1 热量目标

初期可采用：

1. 用户提供基础代谢率时，优先使用用户提供值。
2. 用户未提供基础代谢率时，根据身高、体重、年龄、性别估算。
3. 根据活动系数估算 TDEE。
4. 减脂期设置每日 10%-25% 热量缺口。
5. 对过低热量目标进行安全限制。

### 8.2 蛋白质

减脂期蛋白质建议参考：

- 普通用户：每公斤体重 1.6-2.0 g。
- 力量训练用户：每公斤体重 1.8-2.2 g。
- 体脂较高用户可结合去脂体重计算。

### 8.3 脂肪

脂肪建议不低于总热量的 20%，优先保障激素和基础健康需求。

### 8.4 碳水

碳水由总热量扣除蛋白质和脂肪热量后计算，并根据训练日、休息日进行分配。

### 8.5 安全边界

系统需要提醒：

- 不建议长期极低热量饮食。
- 不建议跳过蛋白质摄入。
- 不建议带伤执行高风险动作。
- 孕期、哺乳期、慢性病、饮食障碍人群需要专业医生或线下营养师介入。

## 9. MVP 范围

### 9.1 必须包含

1. 用户基础档案录入。
2. 减脂目标设置。
3. 每日热量和三大营养素目标生成。
4. 饮食建议生成。
5. 一周训练计划生成。
6. 食材图片识别。
7. 基于食材的轻食方案生成。
8. 用户确认食材重量。
9. 基础风险提醒。

### 9.2 暂不包含

1. 可穿戴设备自动同步。
2. 自动识别体测报告全部字段。
3. 复杂疾病营养治疗方案。
4. 商城、下单和供应链。
5. 教练端 CRM。
6. 社群打卡系统。

## 10. 非功能需求

### 10.1 准确性

- 食材识别结果需要展示置信度。
- 营养结果需要说明为估算值。
- 对缺失关键数据时，Agent 应主动追问。

### 10.2 安全性

- 健康建议必须包含风险边界。
- 对明显不健康目标进行拦截或温和劝阻。
- 用户健康数据需要加密存储。

### 10.3 可解释性

- 计划生成后需要解释核心依据。
- 用户可以追问为什么蛋白质、碳水、脂肪这样分配。

### 10.4 易用性

- 用户无需理解复杂营养学术语即可执行。
- 输出以餐次、动作、步骤为主。
- 关键计划支持复制、分享、保存。

## 11. 页面与交互初稿

### 11.1 用户端

1. 首页：今日目标、今日训练、今日饮食建议。
2. 建档页：身体数据、目标、健康限制。
3. 训练计划页：周计划、单次训练详情、完成打卡。
4. 饮食计划页：营养目标、推荐餐次、饮食建议。
5. 轻食拍照页：上传食材照片、确认食材、生成菜谱。
6. 反馈页：体重、围度、训练完成率、饮食执行率。

### 11.2 教练端，后续版本

1. 学员列表。
2. 学员身体数据趋势。
3. 学员计划查看。
4. 一键调整建议。
5. 周报导出。

## 12. 关键指标

- 建档完成率。
- 首次计划生成成功率。
- 食材识别确认率。
- 轻食方案采纳率。
- 训练打卡率。
- 饮食执行率。
- 7 日留存率。
- 体重或围度有效记录率。
- 用户主观满意度。

## 13. 风险与待确认问题

### 13.1 产品风险

- 用户输入数据不准确，导致计划偏差。
- 食材照片识别和重量估算存在误差。
- 用户可能将 Agent 建议误认为医疗建议。
- 训练动作如果缺少标准演示，可能存在执行风险。

### 13.2 待确认问题

1. 产品优先服务 C 端用户，还是先作为教练工具服务 B 端？
2. 是否需要接入食物营养数据库？
3. 是否需要内置中国常见食材和中餐烹饪方式？
4. 训练计划是否需要动作视频库？
5. 轻食方案是否需要支持一键生成购物清单？
6. 是否需要支持微信小程序、App 或 Web 端？
7. 是否需要教练审核 Agent 生成的计划后再发给用户？

## 15. 初步验收标准

1. 用户完成基础档案后，系统能生成清晰的每日热量和三大营养素目标。
2. 用户能获得一份可执行的一周训练计划。
3. 用户上传食材照片后，系统能识别主要食材并要求用户确认重量。
4. 系统能基于确认后的食材生成至少 1-3 个轻食方案。
5. 每个轻食方案包含食材用量、烹饪步骤、热量和三大营养素估算。
6. 系统能对过低热量、过度训练、伤病风险进行提示。
7. 用户能保存计划，并在后续反馈后获得调整建议。
