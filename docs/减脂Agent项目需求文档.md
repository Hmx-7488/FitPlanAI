# FitPlanAI AI Agent 项目需求文档

## 1. 项目定位

FitPlanAI 是面向减脂、增肌、塑形和健康饮食场景的 AI Agent 应用。系统通过多轮对话、结构化建档、身材照片分析、餐食图片识别、食材图片识别、AI 动作分析、营养计算工具、训练动作知识库、中国饮食知识库和 Agent 工作流，为用户生成个性化饮食计划、训练计划、带图片的轻食菜谱、每日热量缺口/盈余分析、动作纠错建议和阶段复盘建议。

项目不是普通聊天机器人，而是一个具备“理解目标、补全信息、调用工具、生成计划、等待确认、持续调整”能力的任务型 Agent。

## 2. 核心目标

1. 支持用户选择目标：减脂 `fat_loss` 或增肌 `muscle_gain`。
2. 根据用户身体数据、活动水平、训练时间和目标，计算热量与三大营养素。
3. 根据每周训练天数、单次训练时长、训练地点、器械条件和伤病限制生成训练计划。
4. 支持建档和打卡时上传身材照片，辅助估算体脂率、身材类型、体态特征和阶段变化。
5. 支持上传已吃餐食照片，估算每餐摄入，并根据目标计算热量缺口或盈余。
6. 支持上传现有食材照片，确认可用食材后生成带成品图的轻食菜谱。
7. 当用户缺少菜谱所需食材时，提供替代食材或最小购物清单。
8. 结合中国地域、口味、外卖、食堂、家常菜和备餐时间，生成更容易执行的饮食计划。
9. 支持上传训练动作图片或视频，分析动作姿态、关节角度、对称性和常见错误。
10. 通过 RAG 知识库增强饮食建议、训练建议、动作纠错和风险提醒的可靠性。
11. 建立可追溯、可版本化的专业知识层，为计划生成、分析建议、风险审查和问答提供统一依据。
12. 在知识库和业务工具稳定后，提供能够读取用户上下文、解释结果并生成调整草案的聊天 Agent。

## 3. 目标用户

### 3.1 C 端用户

- 想减脂或增肌但不知道怎么吃、怎么练的人。
- 有一定训练基础，希望获得个性化训练和饮食方案的人。
- 工作忙，希望饮食计划省时、易买、易执行的人。
- 经常吃外卖、食堂或家常菜，希望拍照记录热量的人。
- 希望用现有食材快速做轻食的人。
- 希望通过身材照片追踪体型变化的人。
- 希望通过动作视频获得训练纠错的人。

### 3.2 B 端用户

- 健身教练。
- 营养师。
- 私教工作室。
- 健康管理机构。

MVP 优先服务 C 端单用户主链路，后续扩展教练端学员管理。

## 5. 核心业务流程

### 5.1 主 Agent 流程

```text
用户输入目标
-> Agent 判断缺失信息
-> 追问身体数据、训练时间、活动水平、饮食偏好、健康限制
-> 可选分析身材照片
-> 调用营养计算工具
-> 检索饮食/训练/风险知识库
-> 生成饮食计划和训练计划
-> 输出结构化计划
-> 用户打卡反馈
-> Agent 复盘并调整方案
```

### 5.2 食材轻食流程

```text
用户上传现有食材照片
-> 识别食材、估算重量和置信度
-> 用户确认重量和是否可用
-> 检索食材营养数据
-> 优先使用用户确认拥有的食材生成菜谱
-> 缺少食材时给替代方案或购物清单
-> 输出带图片的菜谱、步骤、热量和三大营养素
```

### 5.3 餐食记录流程

```text
用户上传已吃餐食照片
-> 识别菜品、主食、饮品和份量
-> 用户确认或修正
-> 汇总本餐摄入
-> 根据目标计算当日热量缺口或盈余
-> 输出剩余热量、蛋白质缺口和下一餐建议
```

### 5.4 中国饮食计划流程

```text
用户选择地域、口味、饮食场景和备餐时间
-> 检索中国菜品热量库和地域饮食库
-> 结合减脂/增肌目标与营养目标
-> 生成家常、外卖、食堂、便利店方案
-> 输出每餐热量、宏量营养素和点餐/备餐建议
```

### 5.5 AI 动作分析流程

```text
用户上传动作图片或视频
-> 浏览器端 MediaPipe Pose Landmarker 提取 33 个人体关键点
-> 视频按时长自适应采样 12/18/24 帧
-> 后端计算关节角度范围、髋部轨迹、速度控制、左右对称性和重复次数
-> Vision Model 读取代表帧与量化结果，补充动作语义和纠正建议
-> 对照动作标准库和姿态风险规则
-> 输出动作评分、错误项、纠正建议和风险提醒
```

结果必须标记数据来源：

- `hybrid`：MediaPipe 关键点量化 + Vision Model 解读。
- `keypoint_only`：Vision Model 不可用，仅保留关键点计算结果。
- `vision_only`：未形成稳定动态量化，仅提供视觉估算。
- `template`：关键点与 Vision Model 均不可用，仅显示通用模板，禁止描述为真实检测。
- `rejected`：关键点覆盖、遮挡或人物入镜质量不足，拒绝生成评分。

### 5.6 身材照片分析流程

```text
用户上传正面、侧面、背面身材照片
-> 校验光线、姿势、遮挡和拍摄质量
-> 结合身高、体重、围度和体脂秤数据
-> 融合照片估算、体脂秤读数和围度公式结果
-> 输出体脂率区间、置信度、证据来源、体态描述和训练重点
-> 保存分析记录，在同角度、相近画幅和合格质量下对比历史照片
```

身材分析必须遵守以下边界：

1. 照片质量不合格时直接拒绝，不使用 BMI 结果伪装成视觉分析。
2. Vision Model 服务失败时，降级结果必须标记为 `fallback`，且不自动回填档案。
3. 只有状态为 `completed` 且置信度不低于 65% 时，才允许自动回填体脂率。
4. 照片与围度结果属于健身辅助估算，不得描述为医学测量或诊断。
5. 历史照片仅在同一用户、同一视角、相近画幅和质量合格时生成对比结论。

## 6. 用户建档字段

### 6.1 基础身体数据

| 字段 | 说明 | 优先级 |
| --- | --- | --- |
| `gender` | 性别 | P0 |
| `age` | 年龄 | P0 |
| `height_cm` | 身高 | P0 |
| `weight_kg` | 当前体重 | P0 |
| `body_fat_rate` | 体脂率，可由用户输入或照片辅助估算 | P1 |
| `muscle_mass_kg` | 肌肉量 | P1 |
| `bmr_kcal` | 基础代谢，可选 | P1 |

### 6.2 目标与周期

| 字段 | 说明 | 优先级 |
| --- | --- | --- |
| `goal_type` | `fat_loss` 减脂或 `muscle_gain` 增肌 | P0 |
| `target_weight_kg` | 目标体重 | P0 |
| `target_body_fat_rate` | 目标体脂率 | P1 |
| `target_weeks` | 目标周期 | P0 |

### 6.3 活动水平与训练时间

不同用户的活动水平和可训练时间必须影响饮食与训练计划。

| 字段 | 说明 | 影响 |
| --- | --- | --- |
| `activity_level` | 日常活动水平：久坐、轻度、中度、高度、极高 | 影响 TDEE 和热量目标 |
| `training_days_per_week` | 每周可训练天数 | 影响训练拆分和恢复安排 |
| `session_duration_minutes` | 单次可训练时长 | 影响动作数量、组数、有氧时长 |
| `training_location` | 家庭、健身房、户外 | 影响动作和器械选择 |
| `equipment` | 可用器械 | 影响动作库检索 |
| `training_experience` | 新手、初级、中级、高级 | 影响强度、容量和动作复杂度 |
| `preferred_training_time` | 早晨、中午、晚上，可选 | 影响餐前餐后建议 |

活动水平建议枚举：

| 值 | 含义 | 示例 |
| --- | --- | --- |
| `sedentary` | 久坐 | 办公室久坐，几乎不运动 |
| `light` | 轻度活动 | 每周 1-2 次轻运动 |
| `moderate` | 中度活动 | 每周 3-4 次训练 |
| `high` | 高度活动 | 每周 5-6 次训练或体力工作 |
| `very_high` | 极高活动 | 高强度训练、运动员或重体力工作 |

训练时间对计划的影响：

| 每周频率/单次时长 | 减脂建议 | 增肌建议 |
| --- | --- | --- |
| 2 天/30 分钟 | 全身力量 + 短有氧 | 全身基础力量，动作少但保证复合动作 |
| 3 天/45 分钟 | 全身或上下肢拆分 + 有氧 | 全身或推拉腿简化版 |
| 4 天/60 分钟 | 上下肢拆分 + 2-3 次有氧 | 上下肢或推拉腿，增加训练容量 |
| 5-6 天/60-90 分钟 | 力量保肌 + 有氧分配到非腿日 | 肌群拆分，强调渐进超负荷和恢复 |

### 6.4 饮食与健康限制

| 字段 | 说明 | 优先级 |
| --- | --- | --- |
| `diet_preference` | 均衡、高蛋白、低碳、素食等 | P0 |
| `region_preference` | 地域饮食偏好 | P1 |
| `meal_scenario` | 家常、外卖、食堂、便利店 | P1 |
| `prep_time_limit_minutes` | 可接受备餐时间 | P1 |
| `allergies` | 过敏源 | P0 |
| `diet_restrictions` | 忌口 | P0 |
| `injuries` | 伤病限制 | P0 |

## 7. 减脂与增肌策略差异

| 维度 | 减脂 `fat_loss` | 增肌 `muscle_gain` |
| --- | --- | --- |
| 热量策略 | TDEE 减少 10%-25% | TDEE 增加 5%-15% |
| 蛋白质 | 1.6-2.2g/kg | 1.8-2.4g/kg |
| 碳水 | 控制总量，训练日适度保留 | 训练日前后优先保障 |
| 脂肪 | 不低于总热量 20% | 占总热量 20%-30% |
| 饮食重点 | 高蛋白、高纤维、控油控糖 | 高蛋白、足量碳水、干净热量盈余 |
| 训练重点 | 力量保肌 + 适量有氧 | 渐进超负荷 + 足够训练容量 |
| 有氧安排 | 2-4 次/周 | 低频辅助，避免影响恢复 |
| 复盘重点 | 体重下降、围度、体脂、饥饿感 | 体重增长、力量提升、围度、恢复状态 |

### 8.9 RAG 知识库

RAG 不是聊天功能的附属模块，而是计划生成、分析建议、风险审查和聊天问答共用的专业知识层。

| 知识库 | 内容 | 用途 | 优先级 |
| --- | --- | --- | --- |
| 减脂标准库 | 热量缺口、减重速度、蛋白质、平台期和恢复原则 | 减脂计划与复盘 | P0 |
| 增肌标准库 | 热量盈余、训练容量、渐进超负荷和恢复原则 | 增肌计划与复盘 | P0 |
| 食材营养库 | 食材热量、营养素、常见份量和替代关系 | 菜谱和餐食估算 | P0 |
| 饮食规划库 | 餐次分配、外卖、食堂、家常菜和特殊限制 | 饮食计划与替换建议 | P0 |
| 中国菜品热量库 | 家常菜、外卖、食堂菜和便利店组合 | 中式饮食计划 | P0 |
| 中国地域饮食库 | 地域主食、口味和常见菜 | 本土化建议 | P1 |
| 训练原则库 | 训练频率、容量、强度、恢复和周期安排 | 训练计划生成 | P0 |
| 训练动作库 | 动作、肌群、器械、难度和禁忌 | 训练计划 | P1 |
| 动作标准库 | 拍摄要求、动作阶段、常见错误和纠正提示 | 动作分析 | P1 |
| 风险规则库 | 极端饮食、伤病禁忌、过敏源和特殊人群边界 | 安全校验 | P0 |

每个知识块至少包含：

- 标题、正文、分类、主题和标签。
- 来源名称、来源链接、发布日期和最后复核时间。
- 证据等级、适用目标、适用人群、适用条件和禁忌条件。
- 文档版本、知识块版本和启用状态。

检索必须支持：

- 根据用户目标、身体数据、训练水平、饮食限制和当前任务进行元数据过滤。
- 语义检索与关键词检索混合召回。
- 对召回结果进行去重和重排。
- 返回来源、适用条件和依据摘要。
- 当没有可靠知识支持时明确说明“知识库中暂无足够依据”，不得编造来源。

### 8.10 上下文聊天 Agent

聊天 Agent 定位为“健康计划助手”，不是开放式闲聊机器人。第一版优先在饮食计划、动作分析、身材分析和复盘页面提供上下文问答，后续再增加全局聊天入口。

| 能力 | 描述 | 优先级 |
| --- | --- | --- |
| 结果解释 | 解释营养目标、计划、动作和身材分析结果 | P1 |
| 知识问答 | 基于 RAG 回答减脂、增肌、饮食和训练问题，并展示来源 | P1 |
| 读取上下文 | 读取用户档案、今日摄入、训练计划和历史分析 | P1 |
| 调整草案 | 生成食材替换、餐次调整或训练调整方案 | P2 |
| 变更预览 | 展示修改前后热量、营养素和训练安排差异 | P2 |
| 确认后写入 | 只有用户明确确认后才保存计划修改 | P2 |
| 会话摘要 | 保存结构化摘要和关键决策，避免无限保存全部上下文 | P2 |

聊天 Agent 的工具权限分为：

- 只读工具：可自动读取用户档案、今日饮食、训练计划、动作分析结果和知识库。
- 草案工具：可自动计算替换方案和计划差异，但不能直接写入。
- 写入工具：修改饮食计划、训练计划或用户数据前必须展示变更预览并获得用户确认。

第一版不支持疾病诊断、药物建议、自动修改健康限制或在用户未确认时写入计划。

## 10. 安全与边界

1. Agent 不提供疾病治疗、药物调整和临床诊断。
2. 孕期、哺乳期、慢性病、饮食障碍、严重伤病用户需要咨询医生或线下专业人士。
3. 营养、体脂、餐食热量和身材照片分析均为估算。
4. 身材照片属于敏感隐私数据，需要上传示例、隐私提示、删除入口和存储说明。
5. 食材和餐食识别结果必须支持用户确认。
6. 动作分析仅用于训练辅助，不替代线下教练或康复治疗师。
7. 菜谱图片是成品示意图，不保证与用户实际烹饪结果完全一致。

## 12.1 全局聊天 Agent MVP

### 产品边界

第一版聊天 Agent 是现有业务能力的只读自然语言入口，不直接修改用户档案、计划、餐食或打卡数据。

支持：

1. 基于用户档案回答减脂、增肌、饮食和训练问题。
2. 读取用户最新饮食与训练计划，解释计划内容。
3. 根据当前页面携带的上下文回答追问。
4. 调用 RAG 检索并展示引用来源。
5. 对伤病、极端节食、疾病诊断等问题执行风险提示。
6. 保存会话和消息，刷新页面后可以恢复。
7. 使用 SSE 流式返回 DashScope 模型输出。

暂不支持：

1. 自动修改用户档案。
2. 自动生成并覆盖现有计划。
3. 自动写入餐食或打卡。
4. 多人共享会话和教练端介入。

### 核心数据

```text
chat_conversations
├─ id
├─ user_id
├─ title
├─ status
├─ created_at
└─ updated_at

chat_messages
├─ id
├─ conversation_id
├─ role
├─ content
├─ citations_json
├─ context_json
├─ status
└─ created_at
```

### MVP API

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| `/api/chat/conversations` | POST | 创建会话 |
| `/api/chat/conversations?user_id=` | GET | 获取用户会话列表 |
| `/api/chat/conversations/{id}?user_id=` | GET | 获取会话及历史消息 |
| `/api/chat/conversations/{id}` | DELETE | 归档会话 |
| `/api/chat/conversations/{id}/messages/stream` | POST | 发送消息并通过 SSE 流式返回 |

### 流式事件

| 事件 | 数据 |
| --- | --- |
| `meta` | 用户上下文摘要、检索状态 |
| `delta` | 本次生成的文本增量 |
| `citations` | RAG 引用列表 |
| `done` | 已保存的助手消息 |
| `error` | 可向用户展示的错误信息 |

### 安全要求

1. 每个会话请求必须同时校验 `conversation_id` 和 `user_id`。
2. 不允许跨用户读取会话和消息。
3. 不把 API Key、系统提示词和内部异常堆栈返回前端。
4. 医疗诊断、药物、严重伤病和极端节食问题必须输出安全边界。
5. 检索证据不足时明确说明，不生成虚假来源。
6. 第一版工具均为只读工具。

## 14. 验收标准

1. 用户可以选择减脂或增肌。
2. 同一用户选择不同目标时，热量、饮食计划和训练计划明显不同。
3. 用户可填写不同活动水平、每周训练天数、单次训练时长，并生成匹配方案。
4. 久坐用户和高活动用户的热量目标不同。
5. 每周 2 天和每周 5 天用户的训练计划不同。
6. 30 分钟和 90 分钟训练时长对应不同动作数量和训练容量。
7. 食材菜谱优先使用用户确认拥有的食材。
8. 缺少食材时输出替代方案或购物清单。
9. 每个菜谱包含图片 URL 或占位图，以及 `generation_prompt`。
10. 餐食记录能计算减脂缺口或增肌盈余。
11. 风险提醒能覆盖极低热量、过敏、伤病和训练过量。
12. 计划、分析和问答能够返回可追溯的知识来源及适用条件。
13. 当检索不到可靠依据时，系统明确提示证据不足，不生成虚假引用。
14. 聊天 Agent 能读取当前业务上下文，但不会在用户确认前修改计划或档案。
15. 用户确认计划变更前，界面能够展示修改前后差异。
16. 身材照片质量不合格时不生成体脂区间；服务降级结果不得自动回填档案。
17. 身材结果展示视觉、体脂秤和围度公式等证据来源，并保存历史记录。
18. 历史身材照片只有在同角度、相近画幅和质量合格时才生成阶段对比。
19. 动作视频至少使用 12 个采样点进行关键点分析，代表帧数量与量化帧数量必须分别展示。
20. 动作结果中的角度、轨迹、速度、对称性和次数必须来自关键点计算，不由 LLM 虚构。
21. 关键点覆盖不足或人物严重裁切时拒绝评分并展示拍摄建议。
22. 模板结果必须明确标记为非真实检测结果，不能与混合分析或关键点量化使用相同视觉标识。

## 15. 简历项目描述

FitPlanAI 是一个基于 LLM 的减脂与增肌训练饮食管理 AI Agent，支持用户通过多轮对话完成身体数据建档，选择减脂或增肌目标，并根据活动水平、每周训练天数、单次训练时长、训练地点和器械条件生成差异化饮食与训练计划。项目接入多模态餐食、食材、身材照片和训练动作分析能力：用户上传餐食照片后，Agent 可估算每餐摄入并计算热量缺口或盈余；用户上传现有食材照片后，Agent 可确认可用食材并生成带成品图的轻食菜谱；用户上传动作图片或视频后，Agent 可分析关节角度、动作对称性和常见错误。系统结合中国饮食习惯、工具调用、结构化输出和 RAG 知识库，实现可解释、可追踪、可持续调整的 AI 健康管理闭环。
