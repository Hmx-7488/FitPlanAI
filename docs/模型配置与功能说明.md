# 模型配置与功能说明

SlimAgent 使用两种类型的 LLM：**文本 LLM** 和 **多模态 Vision Model**。本文档说明各功能使用的模型、调用方式和配置方法。

---

## 0. 当前实际使用情况

当前推荐配置：

```env
LLM_MODEL=qwen-plus
VISION_MODEL=qwen-vl-plus
LLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
```

API Key 仅保存在本地环境变量中。允许程序检查变量是否存在，但禁止输出、提交或记录 Key。

| 功能 | 模型/引擎 | 能力要求 | 当前状态 |
|------|---------------|----------|----------|
| 计划、聊天、复盘 | `qwen-plus` | 文本 | ✅ |
| 食材与餐食识别 | `qwen-vl-plus` | 图片输入 | ✅ |
| 身材分析 | `qwen-vl-plus` + 围度公式 | 多图与结构化输出 | ✅ |
| 动作关键点 | MediaPipe Pose Landmarker Lite | 端侧 WASM 推理 | ✅ |
| 动作解释 | `qwen-vl-plus` | 代表帧 + 关键点量化结果 | ✅ |
| 菜谱成品图 | `wan2.6-t2i` | 异步文生图 | ✅ |

> 动作分析不再只依赖 Vision Model。MediaPipe 负责可计算的关键点、角度、轨迹、速度和对称性，Vision Model 只负责解释和纠正建议。

## 1. 模型配置

在 `backend/.env` 中配置：

```env
# 文本 LLM（必填）
LLM_API_KEY=your_api_key_here
LLM_BASE_URL=https://api.example.com/v1
LLM_MODEL=qwen3.5-plus

# 多模态 Vision Model（可选，留空则回退到 LLM_MODEL）
VISION_MODEL=qwen-vl-max

# 数据库
DATABASE_URL=sqlite+aiosqlite:///./slim_agent.db
```

### 模型要求

| 配置项 | 用途 | 能力要求 |
|--------|------|----------|
| `LLM_MODEL` | 文本生成（计划、复盘、追问） | 纯文本对话即可，推荐 `qwen3.5-plus`、`gpt-4o-mini`、`deepseek-chat` |
| `VISION_MODEL` | 图片识别（食材、身材、动作、餐食） | **必须支持图片输入**，推荐 `qwen-vl-max`、`gpt-4o`、`gemini-2.0-flash` |

> **注意**：`VISION_MODEL` 留空时，所有视觉功能会回退到 `LLM_MODEL`。如果文本模型不支持图片输入，视觉功能将报错或自动降级到 Mock/模板数据。

## 2. 功能 × 模型对照表

### 文本 LLM（`LLM_MODEL`）

以下功能仅需纯文本能力，由 `workflow.py` 中的 `get_llm()` 统一创建：

```python
def get_llm(max_tokens: int = 1500):
    return ChatOpenAI(
        model=settings.LLM_MODEL,
        temperature=0.7,
        max_tokens=max_tokens,
    )
```

| 功能 | 调用位置 | 节点/函数 | max_tokens | 温度 | 说明 |
|------|----------|-----------|------------|------|------|
| 追问生成 | `workflow.py` | `ask_followup()` | 300 | 0.7 | 档案不完整时生成友好追问语 |
| 饮食计划 | `workflow.py` | `generate_meal_plan()` | 1500 | 0.7 | 生成 3 天饮食方案，含 RAG 食材知识 |
| 训练计划 | `workflow.py` | `generate_workout_plan()` | 1200 | 0.7 | 生成一周训练方案，含 RAG 运动知识 |
| 风险校验 | `workflow.py` | `risk_guardrail()` | 200×2 | 0.7 | 两次调用：检查忌口 + RAG 风险审查 |
| 总结输出 | `workflow.py` | `summarize_plan()` | 600 | 0.7 | 执行建议 + 风险提醒 + 鼓励语 |
| 复盘分析 | `workflow.py` | `review_analyze_checkins()` | 800 | 0.7 | 分析打卡记录，评估执行情况 |
| 次日建议 | `workflow.py` | `review_next_day_advice()` | 600 | 0.7 | 生成明日饮食/运动调整建议 |
| 菜谱生成 | `vision_service.py` | `generate_recipes()` | 1200 | 0.3 | 基于确认食材生成轻食方案 |

### 多模态 Vision Model（`VISION_MODEL`）

以下功能需要**图片输入**能力，由 `vision_service.py` 中的 `_get_vision_llm()` 统一创建：

```python
def _get_vision_llm(max_tokens: int = 1000):
    model = settings.VISION_MODEL or settings.LLM_MODEL  # 留空则回退
    return ChatOpenAI(
        model=model,
        temperature=0.3,
        max_tokens=max_tokens,
    )
```

| 功能 | API 端点 | 调用文件 | max_tokens | 图片输入 | LLM 调用次数 | 说明 |
|------|----------|----------|------------|----------|-------------|------|
| 食材识别 | `POST /api/vision/recognize` | `vision_service.py` | 800 | ✅ 是 | 1 次 | 识别图片中的食材名称和重量 |
| 菜谱生成 | `POST /api/vision/recipes` | `vision_service.py` | 1200 | ❌ 否 | 1 次 | 基于已确认食材生成菜谱（纯文本） |
| 身材分析 | `POST /api/body/analyze` | `api/body.py` | 1400 | ✅ 是 | 1-2 次 | 多角度质量检查、体脂区间、围度融合和历史对比 |
| 动作分析 | `POST /api/pose/analyze*` | `api/pose.py` | 900 | ✅ 是 | 1 次 | MediaPipe 量化结果的动作语义解释与纠正建议 |
| 餐食识别 | `POST /api/meal/analyze` | `api/meal.py` | 600 | ✅ 是 | 1 次 | 照片识别菜品和份量，估算热量 |

> **降级策略**：当 Vision Model 调用失败时，各功能有独立的降级方案：
> - 食材识别 → 返回空列表
> - 身材分析 → 标记为 `fallback`，可使用围度公式或低置信度 BMI 参考，不自动回填档案
> - 动作分析 → 关键点有效时返回 `keypoint_only`；关键点也无效时才显示明确标识的模板参考
> - 餐食识别 → 返回默认家常菜估算值

## 3. 不使用模型的功能（纯计算）

以下功能完全由 Python 代码实现，不依赖任何 LLM：

| 功能 | 实现文件 | 计算方式 |
|------|----------|----------|
| BMR 基础代谢率 | `tools/calorie_tools.py` | Mifflin-St Jeor 公式 |
| TDEE 每日总消耗 | `tools/calorie_tools.py` | BMR × 活动系数 |
| 目标热量 | `tools/calorie_tools.py` | 减脂：TDEE × 0.8；增肌：TDEE × 1.10 |
| 宏量营养素分配 | `tools/calorie_tools.py` | 蛋白质 1.6-2.2g/kg，脂肪占 25%，碳水剩余 |
| 档案完整性检查 | `workflow.py` check_profile | 字段校验 + 数据合理性规则 |
| 热量缺口计算 | `api/meal.py` | 当日已摄入 vs 目标热量 |
| Dashboard 聚合 | `api/dashboard.py` | 数据库查询 + 热量计算 |
| 伤病风险提示 | `api/pose.py` | 规则匹配（膝盖/腰/肩关键词） |
| 动作关键点 | 前端 `services/poseLandmarker.ts` | MediaPipe Pose Landmarker Lite，33 关键点 |
| 动作角度与轨迹 | `services/pose_metrics_service.py` | 向量夹角、髋部轨迹、速度、对称性和次数 |
| 身材围度估算 | `services/body_analysis_service.py` | US Navy 围度公式与多证据加权融合 |
| BMI 计算 | 前端 `utils/calc.ts` | 体重 / 身高² |

## 4. 计划生成完整调用链

一次 `POST /api/plan/generate` 调用涉及的 LLM 调用次数：

```
用户请求
  → parse_user_profile（纯代码）
  → check_profile（纯代码）
  ├─ 档案不完整 → ask_followup（1次 LLM）→ END
  └─ 档案完整：
     → retrieve_knowledge（Chroma 向量检索，无 LLM）
     → calc_calorie（纯计算）
     → generate_meal_plan（1次 LLM）
     → generate_workout_plan（1次 LLM）
     → risk_guardrail（0-2次 LLM，取决于是否有过敏/伤病）
     → summarize_plan（1次 LLM）
     → END
```

**最少 LLM 调用**：3 次（饮食 + 运动 + 总结）
**最多 LLM 调用**：5 次（饮食 + 运动 + 忌口检查 + 风险审查 + 总结）

---

## 5. 复盘分析完整调用链

一次 `GET /api/checkin/review/{user_id}` 调用：

```
用户请求
  → retrieve_knowledge（Chroma 向量检索，无 LLM）
  → analyze_checkins（1次 LLM）
  → next_day_advice（1次 LLM）
  → END
```

**固定 LLM 调用**：2 次

## 7. 推荐模型配置方案

### 方案 A：低成本（国产模型）

```env
LLM_MODEL=qwen3.5-plus
VISION_MODEL=qwen-vl-max
LLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
```

### 方案 B：高质量（OpenAI）

```env

VISION_MODEL=gpt-4o
LLM_BASE_URL=https://api.openai.com/v1
```

### 方案 C：混合方案（文本便宜 + 视觉强）

```env
LLM_MODEL=deepseek-chat
VISION_MODEL=gpt-4o
LLM_BASE_URL=https://api.deepseek.com/v1
```

### 方案 D：全免费（本地模型）

```env

LLM_BASE_URL=http://localhost:11434/v1
```

> 需要本地部署 Ollama，性能和质量取决于硬件配置。

## 8. 故障排查

| 现象 | 原因 | 解决方案 |
|------|------|----------|
| 视觉功能报错 `400 Bad Request` | Vision Model 不支持图片输入 | 配置支持多模态的 `VISION_MODEL` |
| 食材识别返回空列表 | Vision Model 调用失败，降级到空 | 检查 `VISION_MODEL` 配置和 API Key |
| 身材分析显示“降级参考” | Vision Model 不可用 | 检查 `VISION_MODEL`；降级结果不会自动回填 |
| 动作分析显示“仅关键点量化” | Vision Model 失败，但 MediaPipe 有效 | 检查 Vision 配置，关键点量化仍可使用 |
| 动作分析显示“模板参考” | MediaPipe 和 Vision 均未得到真实结果 | 检查本地模型/WASM、拍摄质量和 Vision 配置 |
| 动作分析显示“质量未通过” | 关键点遮挡、裁切或有效帧比例不足 | 固定机位，确保全身和手脚持续入镜 |
| 餐食识别返回 "家常菜" | Vision Model 不可用，降级到默认值 | 配置正确的 `VISION_MODEL` |
| 计划生成超时 | LLM 响应慢 | 检查网络，或增大 `request_timeout` |
| `on_startup` 报错 | FastAPI/Starlette 版本不兼容 | `pip install --upgrade fastapi` |
| `opentelemetry.sdk.resources` 缺失 | chromadb 依赖损坏 | `pip install --force-reinstall opentelemetry-sdk` |
